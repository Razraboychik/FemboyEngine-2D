# Руководство по доступности

[English](accessibility-guide.md) | [Русский](accessibility-guide_RU.md)

Это руководство для разработчиков, которые выпускают игру или работают в
редакторе. Оно описывает три канала вывода, которые даёт движок: встроенный
диктор, мост в системный экранный диктор и субтитры, а также настройки
визуального комфорта: защиту от вспышек, коррекцию цветового зрения,
OLED-сдвиг и темы редактора.

Контракт реализации (структура профиля, путь GPU-композита и семантическое
дерево) находится в [accessibility.md](accessibility.md). Эта
страница — о том, как этим пользоваться.

## 1. Три способа, которыми говорит движок

| Канал | Кто говорит | Когда использовать |
|---|---|---|
| Диктор | сам движок: SAPI, AVSpeech или свой бэкенд | у игрока нет экранного диктора; нужно озвучить контент игры (диалоги, субтитры, события мира); язык контента отличается от голоса ОС |
| Мост в ОС | экранный диктор игрока (Narrator, NVDA, JAWS, VoiceOver, Orca) | у игрока уже настроена ассистивная технология, и он ждёт свой голос, темп и команды |
| Субтитры | только текст | глухие и слабослышащие игроки, а также запасной вариант, когда голоса нет |

Диктор и мост читают одно и то же семантическое дерево, поэтому они не могут
описать два разных интерфейса. Субтитры — отдельная очередь, и она может
работать, пока диктор и мост выключены.

## 2. Быстрый старт в игре

```cpp
Fby::AccessibilityKernel ScopedAccessibility;
ScopedAccessibility.ApplyProfile(ProjectSettings.accessibility); // применяет политику
ScopedAccessibility.SetSpeechOwner(Fby::NarratorOwner::Game);
(void)ScopedAccessibility.StartBridge(ScopedWindow.NativeWindow());
ScopedAccessibility.SetCueLocalization(&ScopedLocalization); // необязательно: локализованные имена

// Раз в кадр, после сборки UI-канваса:
ScopedAccessibility.ProjectCanvas(ScopedUiCanvas);

// Обычные вызовы кадра не меняются:
ScopedAccessibility.ApplyToFrame(ScopedFrame);
ScopedAccessibility.ApplyPostFx(ScopedFrame.postFx);
ScopedAccessibility.FlushSpeech(); // только главный поток
```

`ApplyProfile()` — единая точка применения: он включает настройки рантайма,
политику диктора, политику моста и флаги кадра сразу. Отдельные сеттеры
существуют для тестов и для переключений в рантайме.

`fby_sandbox` подключает ровно этот путь; F2 включает Blind mode, F3 — Deaf
mode, F4 — защиту от вспышек, F5 — цветовое зрение.

## 3. Диктор в игре

Диктор — очередь речи фиксированной ёмкости: приоритеты, подавление повторов в
течение 600 мс на узел, нарезка по границам предложений не длиннее 320 байт и
одно высказывание за раз. Он никогда не вызывает COM-API из рабочего потока;
`FlushSpeech()` — насос главного потока.

| Ключ проекта (`[accessibility]`) | По умолчанию | Действие |
|---|---|---|
| `narration_enabled` | true | главный выключатель речи; при выключении субтитры продолжают работать |
| `narration_focus` | true | объявлять переход фокуса |
| `narration_role` | true | добавлять роль («кнопка», «ползунок») |
| `narration_state` | true | добавлять «включено», «недоступно», «только чтение» |
| `narration_scene` | false | озвучивать полное описание сцены по запросу |
| `narration_world` | true | события мира в Blind mode: контакты, смену тегов |
| `narration_interrupt` | true | переход фокуса обрывает текущую фразу |
| `narration_verbosity` | 2 | 0 молчание, 1 только имя, 2 имя и роль, 3 имя, роль и состояние |
| `narration_rate` | 1.0 | темп речи, ограничен 0.5—2.0 |
| `narration_max_queue` | 8 | длина очереди, ограничена 1—16 |
| `narration_language` | `en-US` | BCP-47-тег голоса |
| `narration_voice` | пусто | точный id установленного голоса; пусто означает «авто по языку» |

Голос следует за **локалью контента**, а не за локалью ОС: игра, переведённая на
японский, говорит по-японски на английской Windows. `SetNarrativeLocale()`
нормализует тег (`pt_BR` превращается в `pt-BR`), а диктор подбирает голос по
установленным: точный тег, затем язык, затем системный голос по умолчанию — с
предупреждением в логе `tts`, когда сработал запасной вариант.

Список **Voice** в настройках проекта (и в секции диктора редактора) показывает
все установленные голоса с их языком и пункт «Auto (by language)». Выбранный
голос сохраняется в `narration_voice` и побеждает поиск по языку, пока остаётся
установленным; если пользователь его удалит, диктор вернётся к политике языка и
запишет это в лог. Список обновляется пунктом «Refresh installed voices», так что
голос, установленный при работающем редакторе, появляется без перезапуска.

Два честных ограничения:

- Движок не поставляет голоса. На Windows он спрашивает оба стека: голоса
  SAPI и современные OneCore через WinRT (SAPI видит их не всегда). macOS даёт
  AVSpeech; на Linux используется speech-dispatcher, если установлены клиентская
  библиотека и демон, иначе диктор молчит. Язык озвучивается, только если для
  него установлен голос; список голосов, панель редактора и лог сообщают о
  несовпадении.
- Надёжность языка на разных платформах — это матрица, а не обещание. Считайте
  контрактом формулировку «озвучивается, если голос есть, иначе — понятный
  запасной вариант».

Длинный текст нарезается: реплика длиннее 320 байт произносится несколькими
высказываниями по порядку. Поток событий мира ограничен `narration_max_queue`:
первыми отбрасываются строки с низшим приоритетом, а счётчик отброшенных виден
у диктора.

## 4. Диктор в редакторе

У редактора своя политика диктора в **Editor Settings → Narrator (editor
window)**; политика игры из проекта никогда не меняет редактор, а политика
редактора никогда не попадает в сборку.

- По умолчанию он **выключен**. Флажок включает озвучивание панелей, фокуса,
  ошибок и смены состояния Play In Editor.
- Включение **Blind mode** заодно включает диктор редактора.
- Фокус на панели произносит имя панели. Фокус на виджете произносит метку и
  роль виджета («Save, button»). Метка и роль приходят из вендорного патча ImGui
  `third_party/patches/imgui/a11y-item-labels.patch`; сегодня роли есть у кнопок,
  флажков, радиокнопок, ползунков, drag-полей, текстовых полей и комбобоксов, а
  пункты меню и selectable объявляют метку, когда ImGui даёт им непустой id.
- Панель может добавить свою строку через `EditorSystem::Announce()` — так в
  голос попадают коммиты, результаты сборки и сообщения консоли.

Пока идёт Play In Editor, голосом владеет игра, и редактор ничего не ставит в
очередь; при этом он продолжает публиковать своё дерево в мост.

## 5. Мост в системный экранный диктор

На Windows движок устанавливает UI Automation fragment provider на окно
процесса. Он не зависит от диктора и может работать при выключенной речи.

Для узла публикуются: `Name`, `ControlType`, `BoundingRectangle`, `IsEnabled`,
`IsKeyboardFocusable`, `HasKeyboardFocus`, `IsOffscreen`, `AutomationId` и
`FrameworkId`. Кнопки и переключатели предоставляют `IInvokeProvider` и
`IToggleProvider`. События фокуса, структуры и состояния поднимаются из кольца
событий дерева; пересборка с тем же набором id молчит.

В редакторе каждое видимое окно ImGui — это панель, а сфокусированный виджет —
её дочерний узел, поэтому экранный диктор отвечает и на «какая панель», и на
«какой элемент управления».

Ключи проекта (`[accessibility]`):

| Ключ | По умолчанию | Действие |
|---|---|---|
| `bridge_enabled` | true | публиковать дерево в ОС |
| `bridge_focus_events` | true | поднимать события смены фокуса |
| `bridge_structure_events` | true | поднимать изменения структуры, когда меняется набор id |
| `bridge_state_events` | true | поднимать изменения свойств состояния |

Как проверить:

1. Запустите игру или редактор и найдите в логе `a11y: accessibility bridge is
   live on Windows`.
2. Откройте Accessibility Insights for Windows или Inspect и подключитесь к
   окну; дерево должно показать корень, панели и сфокусированный элемент.
3. С Narrator или NVDA пройдите интерфейс по Tab: диктор должен следовать за
   фокусом и читать метку.

Ограничения: Linux (AT-SPI2) и macOS (NSAccessibility) сегодня — заглушки;
дерево и диктор там продолжают работать. Эксклюзивный полноэкранный режим может
скрыть окно от некоторых экранных дикторов, поэтому для проверки доступности
лучше использовать безрамочный полный экран.

## 6. Субтитры и Deaf mode

`AccessibilityOverlay` владеет канвасом субтитров и фиксированным хранилищем;
`ComposeUiOverlay()` добавляет его после элементов игры без аллокаций. Звуковые
реплики с id локализации, тайминговые аудио-маркеры и провайдер субтитров голоса
(метка VAD или распознавание речи) питают `SubtitleQueue`.

- Deaf mode выключает Master-шину и показывает субтитры.
- `show_subtitles` показывает их без выключения звука.
- Blind mode дублирует тот же текст в журнал повествования.

## 7. Визуальный комфорт

**Защита от вспышек** — ограничивает изменение яркости за кадр. `flash_threshold`
(0.02—0.45) — допустимая дельта, `flash_gain` (0.05—1.0) — остаточное удержание
более сильной вспышки. Спокойный кадр никогда не затемняется: живой коэффициент
защиты равен 1.0, пока вспышка не обнаружена.

**Цветовое зрение** — матрицы Machado 2009 с силой от 0 до 1. GPU-композит
применяет матрицу и коэффициент вспышки одним проходом
(`accessibility_composite.frag`); `ApplyCpuColorFallback()` делает то же на CPU
для пути без финального композита и не должен совмещаться с GPU-проходом.

**OLED-сдвиг** — `oled_pixel_shift` смещает интерфейс на целые 2 px каждые
`oled_interval_seconds` (1—3600), чтобы избежать выгорания статичной картинки.
Это только презентация: раскладка и попадания указателя не меняются.

**HUD и движение** — `hud_fade_after_idle_seconds` приглушает статичные элементы
HUD после простоя, `motion_scale` (0—1) масштабирует мигание курсора, тряску и
анимацию панелей, а `minimum_contrast_ratio` (1—21) — нижняя граница WCAG 2.2,
которой должна соответствовать тема.

**Комфорт движения проекта** — `[comfort]` в `project.femproj`:

| Ключ | По умолчанию | Потребитель |
|---|---|---|
| `camera_shake_scale` | 1 | стек камер |
| `head_bob_scale` | 1 | политика игровой камеры |
| `motion_blur_scale` | 1 | политика постобработки |
| `fov_scale` | 1 | политика игровой камеры |
| `vignette_scale` | 1 | композит в Play In Editor |

Поведение ввода (hold/tap/pulse/repeat, мёртвая зона, масштаб, инверсия,
однокнопочные схемы) остаётся в раскладке ввода и правилах игры; это не
глобальный переключатель доступности.

## 8. Темы редактора и цвета символов

Редактор намеренно **не** применяет матрицу цветового зрения ко всему окну: это
одновременно изменило бы панели, скриншоты и превью ассетов и заставило бы
авторские цвета лгать. Ту же задачу решают три независимых элемента:

- **Тема панелей** — только оттенки поверхностей: `graphite`, `very-dark`
  (почти чёрный серый, не чистый чёрный), `midnight`, `forest`, `plum`, `amber`,
  `crimson`. `panel_glow` добавляет мягкую акцентную кромку; ноль отключает.
- **Текст** — цвет в sRGB, прозрачность и множитель контраста относительно фона
  выбранной панели. Авторский текст никогда не подменяется темой молча.
- **Цвета символов** — оси, сетка, иконки воспроизведения, гизмо поворота и
  линии графиков. Это правильное место для решения проблемы цветового зрения:
  смысл сохраняется, а панели и превью остаются честными.

**Обводка текста** — отдельный флажок с цветом и размером в пикселях,
отрисовывается вендорным рендерером текста ImGui
(`third_party/patches/imgui/text-outline.patch`) как настоящий контур глифов, а
не фоновая полоса.

Собственные переключатели комфорта редактора (`ide_blind_mode`, `ide_deaf_mode`,
`ide_flash_guard`, `ide_high_contrast`, `ide_reduce_motion`, `ide_color_vision`,
`ide_color_vision_strength`, `ide_flash_threshold`) живут в секции `[editor]`
проекта; полная таблица — в
[Editor Settings](../md/ru/EditorSettingsReference_RU.md#37-доступность-редактора).

## 9. Карта настроек

| Где | Что там |
|---|---|
| Project Settings → Accessibility | флаги рантайма игры, субтитры, цветовое зрение, защита от вспышек, OLED, движение, контраст |
| Project Settings → Narrator (game) | ключи `narration_*` выше |
| Project Settings → Screen reader bridge (game) | ключи `bridge_*` выше |
| Editor Settings → Accessibility (editor window) | ключи `ide_*` для интерфейса редактора |
| Editor Settings → Narrator (editor window) | собственные ключи `narration_*` редактора |
| Editor Settings → Screen reader bridge (editor window) | собственные ключи `bridge_*` редактора |
| Project Settings → Motion comfort (project) | ключи `[comfort]` |

Политика игры хранится в `project.femproj`; политика редактора — в секции
`[editor]` проекта и дублируется в `editor.ini`. Собранная игра читает только
политику `[accessibility]` проекта.

## 10. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Ничего не произносится | `narration_enabled`, Blind mode (для событий мира), лог `tts` об отсутствующем голосе, отбрасывание из-за `narration_max_queue` |
| В редакторе тихо | диктор редактора по умолчанию выключен; включите его или Blind mode |
| Экранный диктор ничего не видит | `bridge_enabled`, строку в логе `a11y`, эксклюзивный полный экран, платформу (Linux и macOS — заглушки) |
| Речь перебивает игру | во время Play In Editor голосом владеет игра, редактор замолкает по замыслу |
| Язык звучит чужим голосом | для `narration_language` не нашлось установленного голоса; в логе указан запасной вариант |
| На Windows пуст список OneCore-голосов | при конфигурации не нашлась проекция C++/WinRT; строка "One-core speech: ..." в логе конфигурации |
| Субтитров нет | Deaf mode или `show_subtitles`, а также реплика с id локализации или провайдер субтитров |

Категории логов: `a11y` (жизненный цикл моста), `tts` (выбор голоса и ошибки
бэкенда), `editor` (повествование панелей).

## 11. Проверка

- `fby_accessibility_narrator_test` — дерево, проекция, роли, дедупликация,
  приоритеты, нарезка, выбор языка, арбитраж владельца и озвучивание фокуса.
- `fby_ui_accessibility_test` — значения профиля по умолчанию, ограничения,
  отображение в кадр, порядок субтитров и композиция оверлея.
- `fby_accessibility_composite_test` — GPU-композит на реальном устройстве Vulkan.
- Ручной прогон: Narrator или NVDA по редактору и по меню собранной игры,
  субтитры в Deaf mode и OLED-сдвиг на статичном ярком экране.
