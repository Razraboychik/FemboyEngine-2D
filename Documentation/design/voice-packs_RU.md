# Голосовые паки (свои голоса) и MPL 2.0

Движок распространяется под MPL 2.0. Голосовые паки позволяют игре говорить
своими голосами, не линкуя в движок ни фонемайзер, ни рантайм моделей, ни
аудиокодек. **Хелпер пака — отдельный процесс**: движок запускает его, пишет
команды в stdin и никогда не загружает его код. Эта граница оставляет чужие
лицензии (включая GPL) вне условий MPL для движка.

## Раскладка пака

```text
Saved/VoicePacks/piper-en-us/
  voicepack.ini
  piper_helper.exe        (piper_helper на Linux/macOS)
  en_US-amy.onnx
  LICENSE.txt             (лицензии самого пака)
```

`Saved/VoicePacks` — корень по умолчанию; `FBY_VOICE_PACKS` его переопределяет.
Ожидается один пак на подкаталог; корень, который сам является паком, тоже
поддерживается.

## voicepack.ini

```ini
id = piper-en-us
name = Piper English (US)
language = en-US
license = MIT (helper), CC-BY-4.0 (model)
helper = piper_helper.exe
model = en_US-amy.onnx
```

| Ключ | Обязателен | Смысл |
|---|---|---|
| `id` | да | стабильный id, виден как `pack:<id>` |
| `name` | да | показывается в списке голосов |
| `language` | да | тег BCP-47 для поиска «auto by language» |
| `license` | нет, желательно | свободный тег лицензии, показывается пользователю |
| `helper` | да | путь к исполняемому файлу относительно папки пака |
| `model` | да | путь к модели относительно папки пака; файл должен существовать |

Пак с отсутствующим файлом или полем пропускается и считается в логе
сканирования. Реестр — только сканер: перечисление голосов никогда не запускает
хелпер, поэтому сломанный пак не может выполнить код, просто попав в список.

## Протокол хелпера

Движок запускает хелпер так:

```text
"<helper>" --voice "<pack id>" --model "<model path>"
```

и пишет в его stdin (UTF-8, `\n` завершает управляющие строки):

```text
VOICE <pack id>
RATE <rate>
SPEAK <byte length>
<utf-8 text>
STOP
QUIT
```

`SPEAK` имеет длину в байтах, поэтому текст может содержать любой байт, кроме
завершающего перевода строки. Хелпер сам отвечает за воспроизведение: он может
использовать любой аудиостек и любую лицензию. Движок его не ждёт и не читает
его вывод (stdout и stderr уходят в null-устройство). `STOP` отменяет текущую
фразу, `QUIT` просит выйти; перед принудительным завершением движок закрывает
stdin.

Эталонный хелпер для тестов — `fby_tts_voicepack_helper`; он записывает
протокол, и `fby_tts_voicepack_test` проверяет его без аудиоустройства.

## Выбор пака

Паки видны в списке голосов рядом с голосами ОС как `pack:<id>` с языком.
Выбор сохраняется в `narration_voice` и направляет речь в пак; выбор голоса ОС
сбрасывает маршрут на пак. Запрос языка (`SetVoice`) предпочитает синтезатор
ОС и откатывается к первому паку с совпадающим основным сабтегом.

## Правила MPL 2.0

1. **Не линковать хелпер и модель в движок.** Это касается статических
   библиотек, in-process ONNX-рантаймов и GPL-фонемайзеров. Граница — pipe;
   её изменение меняет лицензионный анализ.
2. **Не добавлять GPL-заголовки и исходники в этот репозиторий.** Хелпер под
   GPL-3.0 остаётся отдельной программой. Если дистрибутив его включает,
   предоставьте его исходники или письменное предложение, как требует GPL,
   положите рядом файл лицензии и внесите его в инвентарь третьих сторон.
3. **Файлы MPL остаются MPL.** Новые файлы движка (включая `VoicePack.cpp` и
   `Tts.hpp`) покрыты MPL 2.0 репозитория. Изменённый файл движка должен
   оставаться под MPL 2.0, а его исходник — быть доступен получателям, как и
   требует лицензия для всех файлов движка.
4. **Паки — данные, а не код движка.** Модель и хелпер пака могут быть под
   любой лицензией; `license` сохраняется и показывается, но не
   интерпретируется. Авторитетный текст — `LICENSE.txt` пака.
5. **Никаких сторонних блобов в дереве движка.** Паки поставляются как
   скачиваемый контент или отдельный каталог пакета. Репозиторий движка не
   должен начинать содержать GPL-бинарники, веса моделей или их производные.
6. **Граница доверия.** Хелпер запускается с правами пользователя при старте
   речи. Паки — устанавливаемые пользователем программы; лаунчер должен
   показывать `license` и происхождение до включения.

Пример: Piper — MIT, его фонемайзер `espeak-ng` — GPL-3.0. Хелпер, включающий
оба, может распространяться как GPL-программа и работать отдельным процессом;
движок остаётся MPL 2.0, потому что только пишет байты в stdin хелпера. Голоса
моделей имеют собственные лицензии и перечисляются для каждого пака.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Пака нет в списке | в `voicepack.ini` нет поля, либо `helper`/`model` не существует; в логе сканирования он считается пропущенным |
| «helper could not be started» | неверный путь, нет права на запуск или хелпер собран под другую архитектуру |
| Речь молчит без ошибки | хелпер запустился и завершился; смотрите его собственный лог рядом с моделью |
| `pack:` id отклонён | пак не установлен или id с опечаткой |

## Проверка

`fby_tts_voicepack_test` покрывает разбор манифеста (включая пропуск сломанного
пака), перечисление, выбор `pack:`, передачу темпа, точный payload протокола,
`STOP`/`QUIT` и слоистый бэкенд без синтезатора ОС.
