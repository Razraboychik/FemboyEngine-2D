# Контракт безопасности SystemGraph

[English](system-graph.md) | [Русский](system-graph_ru.md)

`SystemGraph` запускает системы одной фазы параллельно только тогда, когда обе
системы явно выставили `SystemAccess::ParallelSafe` и их объявленный доступ не
конфликтует. Последовательный режим — безопасный default для публичного API. Контракт намеренно явный: граф не может
вывести, какие компоненты трогает функция, поэтому система обязана объявить
сервисные биты и, если она делит ECS-данные с другой системой той же фазы, —
маски компонентов.

## Сервисный и компонентный доступ

`SystemAccess` содержит:

- `Reads` / `Writes` — биты сервисов (`kServicePhysics`, `kServiceRenderer`, ...);
- `ComponentReads` / `ComponentWrites` — 256-битные маски из
  `MakeComponentAccessMask<T...>()`.

`Build()` превращает оба вида в рёбра зависимостей; пересечение write/read или
write/write сохраняет порядок регистрации вместо параллельного запуска. Системы
без `ParallelSafe` сериализуются относительно всех соседей по фазе, поэтому
неполное объявление не создаёт тихую гонку. Это явный контракт, а не автоматическая
трассировка компонентов: система, которая ничего не объявила, может войти в
гонку с другой системой на том же компоненте.

## Исключения

Worker-узлы ловят исключения и сообщают через `JobSystem::ReportFault`.
Caller-thread узел в волне из нескольких узлов ловит так же, а затем дожидается
всех отправленных узлов, поэтому stack-хранилище волны и семафор не
разрушаются под работающим worker'ом.

`fby_system_graph_test` проверяет порядок, циклы, неверные маски, сервисные
конфликты, компонентные конфликты и бросающий исключение inline-узел.

## Бюджет scaffold'а

У сгенерированного `CleanRenderExtract` настраиваемый бюджет:

- `FBY_PROJECT_MAX_RENDER_ITEMS`, по умолчанию `16384`;
- `Push()` возвращает `false` и увеличивает `OverflowCount()` вместо тихого
  отбрасывания;
- `Overflowed()` доступен игровому циклу для диагностики.

Рендер-путь остаётся без аллокаций; бюджет — это контракт на старте.
