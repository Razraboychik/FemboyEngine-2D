## 1. Краткое резюме

FemboyEngine2D — двумерный движок на C++26, построенный вокруг data-oriented design и находящийся в статусе Release. Рантайм разделён на отдельные статические библиотеки по роли поставки: игра линкует движок, редактор — движок и библиотеку UI редактора, а офлайн-кукер линкует только библиотеки ассетов. В поставку игры не попадают Dear ImGui, ImGuizmo, ImPlot и TOML-парсер.

Правила проектирования намеренно жёсткие. Состояние симуляции — это простые trivially copyable данные; горячие пути используют фиксированную ёмкость, указатели на функции и арены; кадровые пути не выделяют память; каждая подсистема предоставляет детерминированное состояние с контрольной суммой. Именно это делает роллбэк, горячую перезагрузку, snapshot-тесты и GPU multi-draw практичными, а не теоретическими.

- Ядро: Definitions.hpp, Vector2D/3D/4D, jobs, платформа, plugin ABI, рефлексия Mirror.

- RHI: постоянные кольцевые буферы кадра, 48-байтные sprite-элементы, indirect-отрисовка мешей и один compute-диспатч на linear-blend skinning.

- ECS и физика: реестр EnTT, декларативный SystemGraph, Snapshot v4, мост Box2D v3, цепочки суставов, Verlet-ткань и две модели воды.

- Сеть: NetRollbackSession с кольцом снапшотов на 256 тиков, предсказанием ввода, повтором опоздавших входов и стабильными идентификаторами сущностей.

- Инструментарий: транзакционный CommandStack, AssetDatabase со строками .femeta, watcher, кукер, VFS и редакторы графов на ImNodes с AOT-транспилятором.

Заголовок в Source/Engine/RHI подключается как "Engine/RHI/RHI.hpp"; код редактора использует "Editor/Panels/...". ## 3. Базовые определения и система типов

Source/Engine/Core/Definitions.hpp — единственный источник истины для низкоуровневого словаря. Он определяет FORCEINLINE, помощник статического приведения FemCast<>, проверяемое полиморфное приведение Cast<>, стабильный TypeId и базовый TypeObject. Он подключает Mirror и базовые типы значений, поэтому единица трансляции, включившая его, получает полный контракт без второго include.

```cpp
using TypeId = std::uint64_t;
template <typename T> consteval TypeId StableTypeId() noexcept;

template <typename To, typename From>
[[nodiscard]] FORCEINLINE To FemCast(From&& InValue) noexcept;

template <typename To, typename From>
[[nodiscard]] FORCEINLINE To* Cast(From* InObject) noexcept;
```

StableTypeId<T>() хеширует имя компонента Mirror через FNV-1a. Поэтому отражённые компоненты имеют одну идентичность в инспекторе, схеме снапшотов, plugin ABI и контрольной сумме роллбэка. Класс, не являющийся компонентом, может закрепить независимое от компилятора имя через FBY_TYPE_NAME либо принять хеш сигнатуры компилятора. Cast<> выполняет upcast на этапе компиляции и обходит плоскую таблицу родителей при downcast; неверный downcast возвращает nullptr, а сгенерированная компилятором информация о типах не читается. dynamic_cast и typeid отсутствуют в исходниках движка, и style gate это проверяет.

Базовые типы значений trivially copyable и standard layout. Координатные типы — Vector2D, Vector3D и Vector4D с компонентами X, Y, Z и W в верхнем регистре. Rect — полуоткрытый axis-aligned прямоугольник; Color32 — один упакованный uint32 в порядке 0xAABBGGRR; Handle<Tag> — nullable 32-битный индекс пула, а не указатель. Каждый компонент проверяется компилятором на trivial copyability и standard layout до попадания в снапшот или таблицу плагина.

| Слой | Details |
|---|---|
| Jobs | Пул std::jthread, задачи на указателях функций, ParallelFor с участием вызывающего потока |
| Платформа | Окно/ввод SDL3, нативные диалоги, создание Vulkan surface |
| Плагины | C ABI, проверка layout hash, реестр предоставляется хостом |
| Mirror | consteval-дескрипторы компонентов из указателей на члены, без зависимости от P2996 |

## 4. RHI: Vulkan multi-draw и compute-скиннинг

RHI принимает FramePacket из простых данных и никогда не видит компонент, сущность или строку. Спрайт — один 48-байтный RenderItem: позиция, размер, uvMin, uvMax, слой, упакованный цвет, поворот и флаги. Элементы один раз за кадр сортируются 64-битным ключом (16 бит слой, 40 бит глубина, 8 бит последовательность) и загружаются в постоянно отображённое кольцо инстансов. GPU читает один элемент на инстанс; отдельного vertex-буфера, descriptor set или привязки текстуры на спрайт нет.

Путь мешей параллелен и намеренно устроен иначе. Статическая геометрия один раз загружается в device-local арену и адресуется через MeshHandle. Вершины деформируемых SkeletalAnimation/SkinComponent потоково попадают в host-visible кольцо; один compute-диспатч выполняет linear-blend skinning для всего кадра; результат пишется в device-local буфер SkinnedVertex. MeshVertex занимает 40 байт, SkinnedVertex — 32 байта, обе стороны используют полную column-major Mat4, поэтому 2.5D-камера даёт настоящий z и перспективное деление.

```cpp
MeshVertex     40 B  позиция, uv, цвет, skin range, индексы костей, веса
SkinnedVertex  32 B  однородная позиция (vec4), uv, цвет
RenderItem     48 B  позиция, размер, uvMin, uvMax, слой, цвет, поворот, флаги
```

Отрисовка выполняется одним vkCmdDrawIndexedIndirect на (texture array, слой, класс геометрии). Данные модели, слоя и материала на каждый draw лежат в storage-буфере, индексируемом gl_InstanceIndex, а firstInstance indirect-команды выбирает запись. Поэтому один multi-draw несёт разные model-матрицы без push constant на каждый меш. Vulkan-бэкенд требует shaderDrawParameters; null-бэкенд всё равно проходит полный путь FramePacket, чтобы тесты проверяли реальные данные, а не заглушку.

| Бэкенд | Details |
|---|---|
| Vulkan | Windows/Linux/Android; indirect-путь мешей, compute LBS, загрузчик в рантайме |
| Metal | macOS/iOS; тот же контракт FramePacket, argument buffers Metal |
| Null | Headless CI и серверы; полный путь пакетов/колец без устройства |

По умолчанию в полёте три кадра. Каждый срез владеет кольцом инстансов, кольцом вершин мешей и кольцом индексов, выделенными один раз при создании устройства. Ёмкость — решение на старте, а не аллокация на кадр: значения по умолчанию покрывают 1 048 576 sprite-элементов, 65 536 вершин и 131 072 индекса мешей на срез.

## 5. ECS, планировщик и Snapshot v4

ECS — это реестр EnTT со строгим контрактом компонентов: trivially copyable, standard layout, без строк, контейнеров и vtable. Компоненты — данные; поведение живёт в системах. Кадр имеет четыре фазы: PreUpdate (переменный dt, ввод и стриминг), FixedUpdate (постоянный dt, геймплей и физика), PostUpdate (камера, куллинг, аудио) и Render (извлечение и редактор).

SystemGraph — производственный планировщик. Зависимости задаются явными битмасками after/before; однократная топологическая сортировка строит порядок; цикл или зависимость через фазы приводят к ошибке Build(). Граф вмещает до 64 узлов и использует указатели на функции плюс непрозрачный user-указатель, а не std::function. PluginHost удаляет все узлы с совпадающим user-указателем при выгрузке плагина.

| Фаза | Details |
|---|---|
| PreUpdate | Ввод, события окна, стриминг ассетов; переменный dt |
| FixedUpdate | Геймплей, Box2D, суставы, ткань, жидкость; 0..N шагов постоянного dt |
| PostUpdate | Слежение камеры, куллинг, отправка в микшер; переменный dt |
| Render | Извлечение рендера, сборка UI, отрисовка редактора; раз за кадр |

Snapshot v4 — канонический образ байтов с контрольной суммой. 104-байтный заголовок содержит magic, версию, число сущностей/компонентов, tick/baseTick, размер payload, FNV-1a-сумму, сумму базы, хеш схемы, состояние RNG и поля мирового расширения v3. Сначала идут ECS-записи, поле за полем через Mirror; затем байты расширения для цепочек, ткани, воды и часов эмиттеров, адресуемые стабильными id подсистем, а не handles Box2D. Дельта-снапшот хранит только изменённые записи и всё равно содержит сумму базы, от которой он построен.

```cpp
struct SnapshotHeader {
    char magic[8];              // FBYSNP3\0
    uint32 version;             // kSnapshotVersion
    uint32 flags;               // full or delta
    uint32 entityCount;
    uint32 componentCount;
    uint64 tick, baseTick;
    uint64 payloadBytes, checksum, baseChecksum, schemaHash;
    RngState rng;
    uint32 extensionBytes, extensionOffset;
    uint64 extensionChecksum;
};
```

Каждый зарегистрированный компонент даёт имя, стабильный type id, layout hash Mirror, канонический размер и четыре указателя на функции (has, capture, restore, remove). Layout hash отклоняет изменение поля с тем же размером; schema hash отклоняет другой набор компонентов. Restore не выделяет память: арена снапшотов и таблицы сущностей фиксированы в Initialize().

## 6. Физика: Box2D v3, цепочки, ткань и вода

Заголовок физики не включает box2d.h. RigidBody2D и Collider2D хранят упакованные b2BodyId/b2ShapeId в uint64_t, поэтому геймплей, scene IO и сетевой слой компилируются без C API. PhysicsSystem — единственная единица трансляции, знающая о существовании Box2D. Единицы заданы явно: Box2D работает в метрах, рендерер в пикселях, а PhysicsDesc::pixelsPerMeter — единственная точка преобразования.

| Модель | Details |
|---|---|
| Твёрдые тела | Мир Box2D v3, фиксированный шаг, события контактов, флаг телепорта |
| Верёвка / цепь | Цепочка капсульных звеньев с distance- или revolute-суставами; якоря — существующие тела |
| Ткань | Verlet-сетка 32x32, ограничения Гаусса-Зейделя, overlap-запрос к формам Box2D |
| Вода | Аналитические волны GerstnerField и ShallowWaterGrid на mdspan |

Верёвка — не специальное тело. Это цепочка небольших твёрдых звеньев; верёвка использует distance-суставы, жёсткая цепь заменяет каждый distance на revolute с угловыми лимитами. Система жёстко ограничивает число цепочек, звеньев и суставов и ничего не аллоцирует на кадровом пути. Она владеет созданными звеньями и никогда — якорными сущностями; порядок Shutdown важен, потому что уничтожение мира Box2D инвалидирует все сохранённые id.

Ткань — Verlet mass-spring сетка, проецируемая фиксированным числом итераций Гаусса-Зейделя и затем выталкиваемая из существующих форм Box2D. Это не второй мир коллизий и не дублирование геометрии уровня. CPU пишет позиции MeshVertex; рендерер передаёт их тем же деформируемым путём, что и скинированный меш, поэтому ткань не добавляет второй путь отрисовки. Закреплённая вершина — просто invMass = 0.

Две модели воды живут в одной системе. GerstnerField — небольшая сумма трохоидальных волн: детерминированная, аналитическая, без аллокаций, с якобианом для появления пены на гребнях. ShallowWaterGrid хранит поле высоты/скорости в mdspan-представлениях над фиксированными массивами и интегрирует линеаризованные уравнения мелкой воды с ограниченным числом CFL. Ни одна модель не знает о RHI; рендерер сэмплирует поле или загружает его представление высоты как R32F-текстуру.

## 7. Сетевой роллбэк и Snapshot v4

NetRollbackSession связывает Snapshot v4, CommandLog, Pcg32 и GameplayState. Сессия владеет фиксированным кольцом полных снапшотов (один на симулированный тик), кольцом ввода на игрока, картой стабильных NetEntityId в локальные EnTT id и циклом повтора. Всё после Initialize() не аллоцирует память: арена снапшотов, таблицы сущностей, кольца ввода и метаданные кадров имеют фиксированную ёмкость. Колбэк симуляции — указатель на функцию плюс void*, а не std::function.

Когда удалённый ввод приходит с опозданием, сессия восстанавливает снапшот непосредственно перед самым ранним исправленным тиком, восстанавливает RNG и курсор CommandLog из того же слота, повторно применяет структурные команды, ресимулирует затронутые тики с исправленным вводом и предсказанием для всё ещё отсутствующих входов, снимает новые снапшоты и сообщает, какие кадры реально изменились.

| Константа | Details |
|---|---|
| kMaxNetPlayers = 8 | Ёмкость кольца ввода и массива входов тика |
| kMaxRollbackTicks = 256 | Глубина истории снапшотов для коррекции |
| kMaxNetEntities = 4096 | Таблица стабильных сетевых сущностей |
| kInputRingCapacity = 256 | Окно перезаписи опоздавшего ввода |

NetInputFrame занимает 24 байта и использует знаковые 16-битные fixed-point оси, а не float: битовый шаблон float не гарантированно переживает другой компилятор, а симуляция должна быть чистой функцией входных битов. Статус кадра каждого игрока — Confirmed, Predicted или Missing. Опоздавший ввод перезаписывает предсказание на месте в том же тике, что и требуется для повтора.

NetEntityId назначается авторитетом (или локальным пиром для локально принадлежащих объектов) и никогда не выводится из EnTT id. Восстановленный снапшот, другой порядок спавна или другой аллокатор не должны его менять. GameplayState — 64-битная маска, поэтому всё реплицируемое состояние помещается в один регистр, а контрольная сумма — одно multiply-fold на сущность. CommandLog фиксирует структурные spawn/despawn/add/remove, поэтому роллбэк повторяет и структуру, и значения.

## 8. Пайплайн ассетов и инфраструктура редактора

Компонент никогда не хранит путь. Он хранит небольшой AssetHandle с проверкой поколения, указывающий на строку таблицы метаданных AssetDatabase. Строка владеет стабильными AssetId/GUID, видом ресурса, исходным и приготовленным путями, списком зависимостей и настройками импорта. AssetHandle::generation обнаруживает переиспользованный слот; AssetMeta::contentGeneration позволяет рендереру или кешу сравнивать версии содержимого. Горячая перезагрузка никогда не показывает наполовину обновлённый ассет: правки готовятся и фиксируются атомарно.

```cpp
[[asset]]
guid = "018f0c2e-..."
type = "texture"
source = "atlas/orb.png"
cooked = "atlas/orb.ftex"
format = "bc7_srgb"
depends = ["atlas/atlas.toml"]

[import]
generate_mips = true
max_size = 2048
```

AssetDatabaseWatchSystem следит за исходными папками через OS API и складывает изменённые пути в фиксированное SPSC-кольцо. Поток watcher никогда не меняет базу или RHI; Poll() выполняется в потоке редактора, находит AssetHandle, планирует кукинг, готовит новые метаданные, фиксирует их, увеличивает поколение содержимого и рассылает уведомления о перезагрузке. Свободный PNG/WAV/WebM без строки .femeta импортируется автоматически с детерминированными id и настройками по умолчанию.

CommandStack — движок undo/redo редактора. Правка инспектора или перетаскивание ImGuizmo — одна транзакция: BeginTransaction, Record одной или нескольких сущностей, Commit. Записанный компонент хранится как разреженная байтовая дельта, поэтому перемещение одного Vector2D в 20-килобайтном SkeletonComponent стоит десятки байт. Хранилище — фиксированный массив команд плюс одна арена payload; никакого operator new, std::function и исключений на пути правки. Стек существует только в редакторе и не линкуется в игру.

| Инструмент | Details |
|---|---|
| VFS | Монтирует архивы .fempak и свободные каталоги в одно пространство путей |
| VFS | Детерминированный порядок чтения, range-чтение, без аллокаций на файл в горячем пути |
| fby_fempak | Кукер текстур/аудио/локализации; байт-в-байт совпадает с импортёром редактора |
| fby_loc_tool | TOML локализации -> пакет FlatBuffers |

## 9. Визуальные графы и AOT-транспилятор

Material Graph — небольшой DAG в трёх плоских массивах фиксированной ёмкости: узлы, пины и параметры. Целый материал — одно trivially copyable значение, которое можно memcpy-ить, снимать в undo-системе и хешировать без аллокатора. Компилятор проверяет ровно один выходной узел, подключённость обязательных пинов, совместимость типов и отсутствие циклов, затем генерирует одну GLSL-временную переменную на узел. Никакого интерпретатора и диспатча на кадр: материал стоит ровно столько, сколько стоит его сгенерированный шейдер. Хеш не включает UI-позиции, поэтому перетаскивание узла не перекомпилирует шейдер.

| Ограничение | Details |
|---|---|
| MaterialGraph nodes = 128 | Больший материал — признак проблемы дизайна, а не повод растить рантайм |
| MaterialGraph pins = 384 | Каждый входной слот каждого узла, непрерывно по узлу |
| MaterialGraph params = 64 | Payload скаляра, vec2, vec3, цвета, слоя атласа и texture sample |
| LogicGraph nodes = 128 | Документ редактора — один POD на 10 КиБ |
| LogicGraph links = 256 | Разреженная таблица связей; одна транзакция на правку ребра |

NodeCanvasPanel — транзакционный холст ImNodes. Панель предоставляет таблицу CanvasModelOps из обычных указателей на функции и void*; холст не видит виртуального интерфейса. Холст владеет только состоянием взаимодействия и открывает ровно одну транзакцию CommandStack на перетаскивание или правку ребра. Поскольку весь граф зарегистрирован как один внешний буфер, перемещение узла записывает 8-байтный Vector2D, а не весь граф на 7 КиБ.

VisualScript компилирует LogicGraph в канонический байткод с топологической проходкой Кана; цикл — ошибка компиляции, а не переполнение стека в рантайме. VM исполняет ровно тот артефакт, который поставляет кукер. Для релиза AotTranspiler генерирует одну плоскую единицу трансляции C++26 с одной функцией на событие и без зависимостей от движка, кроме AotAbi.hpp; AotBuilder запускает clang/g++ -O3 -shared в фоновом jthread, а редактор опрашивает его состояние, не блокируя кадр. Сгенерированный модуль несёт хеш графа и каждый LayoutHash компонента; загрузчик проверяет их до первого вызова.

```cpp
LogicGraph -> GraphCompiler -> байткод -> VM (PIE)
                         \-> AotTranspiler -> C++26 -> clang/g++ -O3 -shared -> плагин

MaterialGraph -> проверка типов -> GLSL -> glslang -> SPIR-V -> VkPipeline
```

## 10. Контроль качества и верификация

Release candidate проверяется 21 исполняемым файлом CTest: rollback replay, RNG/noise, сетевой роллбэк, indirect mesh smoke, script VM, script AOT, PinkUI, DSP mixer, audio cook, material graph, video, texture cook, метаданные ассетов, animation timeline, editor command stack, инфраструктура редактора, graph editor, расширения физики, доступность UI, P3 integration и контракт Definitions. Тесты — обычные исполняемые файлы без фреймворка, поэтому работают headless и на консольном devkit.

| Ворота | Details |
|---|---|
| ctest | 25/25 проходят; GPU не требуется для headless-подмножества |
| CheckStyle.py | PascalCase-имена, требуемое дерево, отсутствие Vec2/3/4, RTTI-токенов и кириллицы, Allman, скобки |
| clang-format | Allman, 4 пробела, 120 колонок, обязательные скобки |
| clang-tidy | Параметры In*, выходы Out*, локальные Scoped*, без затенения типов |
| RTTI scan | dynamic_cast/typeid запрещены в исходниках; код движка не использует информацию типов компилятора |

Style gate намеренно проверяет репозиторий, а не только diff. Новый файл с именем в нижнем регистре, алиасом Vec2, комментарием в конце строки или кириллицей падает на ревью до попадания в main. Комментарии только на английском, одной строкой, над кодом и без точки в конце; единственные оставшиеся комментарии в конце строки — два подавления NOLINT, требуемых clang-tidy.

```cpp
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DFBY_BUILD_TESTS=ON
cmake --build build --parallel 8
ctest --test-dir build --output-on-failure
python Source/Tools/Dev/CheckStyle.py
```

Добавление языка означает добавление колонки перевода и новой секции; переписывать стили или делать отдельную вёрстку не нужно.
