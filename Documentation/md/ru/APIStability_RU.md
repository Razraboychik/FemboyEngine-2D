# Стабильность API и форматов данных

Движок держит три независимых контракта стабильности. Они меняются отдельно,
поэтому изменение рендера не требует миграции сцены, а мод не может наблюдать
внутренний C++ layout.

## 1. Стабильное host API

`Engine/Core/ApiVersion.hpp` определяет `kEngineApiVersion`. Host или расширение
редактора ориентируются на это значение и используют заголовки, названные
стабильными в документации: C plugin ABI в `Engine/Core/PluginAPI.h`, безопасный
mod ABI в `Engine/Modding/ModAPI.h`, формат сцены в `Engine/ECS/Scene.hpp` и
формат снапшота в `Engine/ECS/Snapshot.hpp`.

Всё остальное в `Source/Engine` — внутреннее. Внутренние заголовки могут меняться
в любом релизе без цикла deprecation; включать их из плагина не является
поддерживаемым контрактом.

## 2. Безопасный mod ABI

`FbyModApi` — C-структура с ведущими `struct_size` и `abi_version`. Вызывающий
проверяет `FbyModApiHas` перед обращением к добавленному полю. Через границу не
передаются `std::string`, `std::vector`, указатели в ECS-чанки или C++-объекты;
сущности — непрозрачные 32-битные handles, команды применяются в безопасной точке
flush.

Новая возможность добавляет function pointer и увеличивает minor ABI. Удаление
или перестановка существующего поля — ломающее изменение и требует новой major
линии ABI.

## 3. Сериализованные форматы

| Формат | Константа | Текущее значение |
|---|---|---|
| Scene TOML и binary | `Scene::kSceneVersion` | 2 |
| ECS snapshot | `Ecs::kSnapshotVersion` | 5 |
| Prefab binary | `PrefabSystem::kBinaryVersion` | 1 |
| Command log | `Ecs::kCommandLogVersion` | 4 |
| Skeleton asset | `Ecs::kFesklVersion` | 1 |

Читатель отвергает формат новее, чем понимает, и сообщает ожидаемую версию.
Миграция добавляется до того, как writer начнёт выдавать новую версию. Старые
файлы никогда не перезаписываются на месте во время чтения.

## 4. Deprecation

Публичное объявление, которое заменяется, помечается `FBY_DEPRECATED`, а
сообщение называет замену. Оно остаётся доступным минимум одну minor-линию.
Релиз удаления фиксируется в changelog; contract test проверяет константы версий
и layout стабильных типов.

## 5. Contract tests

`fby_api_contract_test` проверяет:

- константа mod ABI совпадает с `FBY_MOD_API_VERSION`;
- константы сцены и снапшота совпадают с каноническими заголовками;
- стабильные ABI-записи являются standard-layout;
- полный `FbyModApi` проходит `FbyModApiHas`, а проверка за `struct_size` и
  null API не проходят;
- текущие версии печатаются в логе теста для release-записей.

Любое изменение layout стабильной записи должно обновлять тест и константу
версии в том же коммите.
